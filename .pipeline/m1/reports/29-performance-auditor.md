Confirmed OK: access log, roles list and employees list are paginated server-side with max 100 (setup.types.ts:66-116); `role_permissions` has a composite PK `(role_id, permission_key)`, which covers the role_id lookups. The `key`-based lookup (`listRoleKeysByKeys`, filter by permission_key) has no supporting index, which is fine at this size; add `index(permission_key)` if roles grow past ~100. `screens`/`permissions` are small reference tables. Transactions contain DB work only, with no external calls.
