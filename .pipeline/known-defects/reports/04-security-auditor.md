# Report 04 — security-auditor — db:reset guard (BR-KD-30, 35, 52)
Scope: `git diff main...HEAD` for backend/scripts/db-reset.ts, backend/scripts/prepare-test-db.ts. No reset was run; driver parsing was checked offline via `postgres(url).options` (no connection).

Result: guard is sound for the normal cases (userinfo@host, uppercase host, `localhost.`, ports, `_test` suffix, NODE_ENV, wrong confirm). One regression bypass (empty DB name) and parser mismatches with the driver.

| id | severity | area | file:line | finding | suggested fix |
|---|---|---|---|---|---|
| SEC-1 | blocker | backend | backend/scripts/db-reset.ts:68-101 | Empty DB name bypasses the confirm. `confirm = DB_RESET_CONFIRM ?? ""` plus `confirm !== dbName` is false when both are "". Scenario: dev runs `DATABASE_URL=postgres://postgres:pw@localhost:5432 bun run db:reset` (or `.../`), no DB_RESET_CONFIRM. Guard sees dbName "", local host, confirm "" === "" so it passes. postgres.js then connects to `PGDATABASE`, else the user name (`postgres`), and `DROP SCHEMA public CASCADE` wipes it (e.g. PGDATABASE=diecast = the dev DB). Same hole for `--allow-remote` on a remote host with an empty path. Regression: the old code compared `process.env.DB_RESET_CONFIRM !== dbName` (undefined !== "" refused). Verified: URL `postgres://postgres:pw@localhost` + PGDATABASE=diecast gives guard db "" and driver db "diecast". | Refuse (exit 2) when `dbName === ""`. Require a non-empty confirm: `confirm === "" \|\| confirm !== dbName` in both branches. |
| SEC-2 | major | backend | backend/scripts/db-reset.ts:42,93,155 | Guard and driver read the URL differently, so the checked target is not always the one wiped. (a) No port in URL: guard assumes 5432, postgres.js uses `PGPORT` first. Scenario: dev has `PGPORT=6543` (tunnel to staging) and `DATABASE_URL=...@localhost/x_test`; guard sees 5432 and skips the confirm, wipes the tunnelled DB. (b) Userinfo with a literal `@` and `,` (unencoded password): `postgres://a@b,prod.example.com:p@localhost:5433/x_test` — guard host `localhost` (local), driver hosts `["b","prod.example.com"]`. Verified offline. Password fragments also go to DNS. (c) Percent-encoded DB name: guard decodes (`prod%2F..` becomes `prod/..`), driver uses the raw path, so guard name and wiped name can differ. | Make the driver the single source of truth: `const o = postgres(rawUrl).options` (no connect) and run the guard on `o.host`, `o.port`, `o.database`. Refuse if `o.host.length !== 1`. Or reject URLs with a comma in the authority, any `%` in the path, or no explicit port. Delete `PGHOST/PGPORT/PGDATABASE/PGUSER` from the env passed to children and the in-process client. |
| SEC-3 | minor | backend | backend/scripts/db-reset.ts:14 | `[::1]` passes the guard but postgres.js parses its host as `[`, so IPv6 targets fail to connect (fails closed, not a bypass). `127.1`, `0.0.0.0`, other loopback spellings are refused as non-local (fails closed). | Optional: strip brackets before the driver, or drop `[::1]` from the set and document. Covered by SEC-2 fix. |
| SEC-4 | minor | backend | backend/scripts/db-reset.ts:61 | `NODE_ENV === "production"` is case-sensitive; `Production` passes. Exported `DB_RESET_CONFIRM=diecast` in a shell profile permanently disables the dev-DB guard. | `.toLowerCase()` the NODE_ENV compare. Note in docs: pass the confirm inline, never export it. |

Checked, no finding
- userinfo trick `postgres://localhost@prod.example.com/x_test`: WHATWG host is `prod.example.com`, refused as non-local; driver agrees.
- `?host=`, `?dbname=`, `?database=`, `?port=` query overrides: ignored by the driver (host/db/port come from the path/authority).
- Port `05433` normalises to 5433 in both. Case `Diecast_TEST` does not match `_test`. `LOCALHOST` accepted (same as the driver); `localhost.` refused.
- Wrong confirm refused in all branches (exit 2, before any connection). `--allow-remote` needs the matching confirm (except SEC-1).
- Secrets: target printed as host:port/db only; scrub covers raw + decoded DB password and SEED_USER_PASSWORD on child output and step errors; invalid-URL refusal does not echo the URL. Seed password reaches bootstrap only via child env. No leak found.
- prepare-test-db: `resolveTestDatabaseUrl` requires `_test` suffix, set, differs from DATABASE_URL; it does not check host, but the child db-reset guard does (no `--allow-remote` passed), so a remote DATABASE_URL_TEST is refused. Child env sets DATABASE_URL explicitly, so `.env` cannot override it. A stray `DB_RESET_CONFIRM` that differs from the test DB name fails closed (exit 2). An empty-path URL cannot pass here (name must end `_test`).
- CI (`ci.yml:46`) targets local `diecast_test` on 5432 without a confirm: allowed by BR-KD-30.
