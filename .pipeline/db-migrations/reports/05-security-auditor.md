# Report 05 — security-auditor — db-migrations (diff main...HEAD, spec v1)

Result: 1 blocker, 2 major, 3 minor. Nothing run against a non-scratch DB. pg_dump is not installed here, so
the dump-permission finding is from pg_dump/libpq semantics + the code, not from a run. The guard-bypass
finding was reproduced by parsing only (no connection).

Checked and fine:
- No shell anywhere: `Bun.spawn(["pg_dump","--format=custom","--file=..."])` is an argv array. DB URL pieces are
  never on the command line; host/port/db/user/password go via PG* env (not visible in `ps` args). No argument injection.
- Password never printed: label is host:port/db; stderr and errors go through `scrub()`.
- Order is right: bad URL / missing MIGRATE_CONFIRM refuse (exit 2) before any connect or dump; nothing pending
  -> no dump, no write; dump failure / empty file -> file removed, refuse, nothing applied.
- All SQL in migrate.ts is constant (lock key is a number literal); journal insert is parameterised.
- `backend/backups/` is ignored (`git check-ignore` confirms).
- CI step: no secrets (service-container creds only), no user-controlled input in the shell block.

## Findings
| id | severity | area | file:line | finding | suggested fix |
|---|---|---|---|---|---|
| SEC-1 | blocker | backend | backend/scripts/db-migrate.ts:65-66,74 | Backup dir and dump are created with the default umask (dir 0755, pg_dump file 0644). The dump holds the whole real DB (password hashes, refresh tokens, QR token digests, supplier bank details). Scenario: UAT/prod box (or shared plant PC) has more than one OS user; any local user, or any process of another account, runs `cat backend/backups/diecast_uat-*.dump` and `pg_restore`s it to read everything. Backups also stay on disk forever. | `mkdirSync(BACKUPS_DIR,{recursive:true,mode:0o700})` and `chmodSync(BACKUPS_DIR,0o700)` if it already exists; set `process.umask(0o077)` before spawning so the file is born 0600; `chmodSync(file,0o600)` after as a belt. Add a test that checks the mode bits. |
| SEC-2 | major | backend | backend/scripts/lib/migrate.ts:157-193 (used at db-migrate.ts:35,45) | The guard and the driver read the URL differently, so the "usual local test DB" test can be passed by a remote host. postgres.js decodes the authority (`decodeURIComponent`) and splits on `,` into several hosts; `parseTarget` only rejects a literal `,`. Reproduced (parse only): `postgres://x@prod.example.com%2Cy@localhost:5432/x_test` -> guard: `localhost:5432/x_test usual=true`; driver: hosts `["prod.example.com","y@localhost"]`. Scenario: a wrong or tampered `DATABASE_URL` in `.env`/CI variable points at a real-data DB whose name ends `_test` (e.g. a UAT copy `diecast_uat_test`); `db:migrate` skips MIGRATE_CONFIRM and the pg_dump and migrates it. Also: guard decodes the db name (`x%5Ftest` -> `x_test`) but the driver sends the raw `x%5Ftest`, and pg_dump gets the decoded one, so guard / driver / pg_dump can name three different things. Needs a real-data DB named `*_test`, hence major not blocker. | After building the client, compare what it will really use: `sql.options.host` must be exactly `[target.host]`, `sql.options.port` `[Number(target.port)]`, `sql.options.database === dbName`; otherwise exit 2. Or reject if `decodeURIComponent(authority)` contains `,` or `@`, or if the raw path contains `%`. Put this in `parseTarget` so db:reset can reuse it. |
| SEC-3 | major | backend | backend/scripts/db-reset.ts:29-103 (guard unchanged in this diff, now also the entry to migrations) | `db:reset` has the same blind spot and is destructive: it only checks `new URL().hostname`. `postgres://x@prod.example.com%2Cy@localhost/diecast` passes as local + usual name `diecast`, then `DROP SCHEMA public CASCADE` runs against `prod.example.com`. Pre-existing, but this diff rewrote the step list and the spec relies on this guard (BR-MIG-09, BR-KD-30). | Reuse the fixed `parseTarget` (SEC-2) in db-reset instead of its own copy. Open an issue if out of scope for this branch. |
| SEC-4 | minor | backend | backend/scripts/prepare-test-db.ts:34-37 | New auto-wipe: on journal mismatch `db:test:prepare` runs `DROP SCHEMA public/drizzle CASCADE` with no host check; the only guard is "name ends in `_test`" (`resolveTestDatabaseUrl`). Before, `push --force` did not wipe the whole schema. Scenario: `DATABASE_URL_TEST` points at a shared/remote `*_test` DB (e.g. a staging copy with real rows) that another branch migrated further -> next `db:test:prepare` silently drops everything. | Rebuild only when the host is local (same LOCAL_HOSTS test); for a non-local host refuse and say so. |
| SEC-5 | minor | backend | backend/scripts/db-migrate.ts:74-82 | pg_dump env is `...process.env` plus PGHOST/PGPORT/PGDATABASE. Other inherited libpq vars can still redirect or weaken it: `PGHOSTADDR` (connects to that IP regardless of PGHOST), `PGSERVICE`, `PGOPTIONS`, `PGSSLMODE`. The URL's `sslmode=require` is not forwarded, so a remote dump may run in plaintext (`prefer`), exposing the password and all data on the wire. Scenario: operator has `PGHOSTADDR` in the shell -> the backup is taken from a different server than the one migrated, and the check "dump non-empty" passes. | Build the env from scratch: copy only PATH/HOME/LANG, then set PGHOST/PGPORT/PGDATABASE/PGUSER/PGPASSWORD and `PGSSLMODE` from the URL's `sslmode` (default `require` when host is not local). Drop all other `PG*`. |
| SEC-6 | minor | backend | backend/scripts/db-migrate.ts:66 | `dbName` goes into the file name unsanitised. A db name with `/` or `..` (from `%2F` in the URL) moves the dump outside `backend/backups/` (writable path chosen by whoever sets DATABASE_URL); with `/` and no such dir, pg_dump fails and it refuses (safe). Low risk, input is operator-controlled. | `dbName.replace(/[^A-Za-z0-9_.-]/g, "_")` for the file name only. |

## Not a finding (noted)
- MIGRATE_CONFIRM is an env var, so a shell profile or CI can make it permanent; it is bound to one db name, so
  only that DB is affected. Accepted by the spec (BR-MIG-17).
- `Migration X failed: <pg message>` can echo row values (unique-violation detail) into the console log. Fine for local use; keep it out of any shared log shipping.
- `new URL("..", import.meta.url).pathname` percent-encodes spaces, so a repo path with spaces breaks BACKUPS_DIR / MIGRATIONS_DIR. Correctness, not security.
- `tests/scripts/db-migrations.test.ts` has no check for backup file mode or for the multi-host URL; add both once SEC-1/2 are fixed (via a test-writer finding, not by the developer).
